Architecture: Event-Driven Dual Storage Feature Pipeline

Inspired by PostHog’s high-throughput event pipeline. Events enter through edge REST/Kafka gateways, stream through sliding window aggregators, atomically update low-latency Online Storage (Redis / Memory), and micro-batch flush to Columnar OLAP (DuckDB / ClickHouse) for mathematically leak-free point-in-time ASOF training joins.

1. Ingestion Layer

PostHog-compatible /capture and /batch endpoints. Sub-millisecond queuing with idempotency keys.

2. Stream Processor

Calculates rolling sliding-window aggregations (10m, 1h, 24h, 7d): counts, sums, averages, and unique device counts.

3. Online Store

Sub-5ms point lookups for live ML inference. Redis hash & memory backends with automatic TTL lifecycle management.

4. Offline OLAP Store

Vectorized columnar execution (DuckDB & ClickHouse). Supports temporal ASOF joins eliminating target data leakage.

Time-Travel: Point-in-Time Correct (ASOF) Joins

The ultimate data engineering test: Zero Data Leakage. When generating historical ML training datasets, features MUST reflect the entity's exact state at the observation timestamp T_obs. Events occurring at T_obs + 1ms are strictly omitted.

How VortexFS Prevents Target Leakage

✓ Past Events (Window Aggregated) ● Observation Point (T_obs) ✗ Future Events (Strictly Filtered)
